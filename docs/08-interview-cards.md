# 08. Agent 评测高频面试题与精选答题卡片 (23 题全景版)

---

## 📌 第一部分：概念与方法论

### Q1: Agent 行业的测试和传统软件测试有哪些根本不同？
* **答题要点**：
  1. **非确定性**：同一输入多次运行输出不同，传统确定性断言失效；
  2. **过程胜于结果**：Agent 可能误打误撞给出正确答案但中间步骤全错，必须识别失败模式与发生频率；
  3. **失败面骤增**：规划、工具调用、多轮交互、多 Agent 协作处处是单点故障；
  4. **Benchmark 污染风险**：公开榜单题目可能泄露进预训练集，必须用私有数据集盲测；
  5. **裁判偏差**：LLM-as-a-Judge 自身存在自我偏好、首位偏差和冗长偏差。

---

### Q2: 什么是评估驱动开发 (EDD)？
* **答题要点**：类比传统软件工程的 TDD。在动手开发 Agent 之前，先定义“成功的业务标准”，构建黄金基准测试集（Golden Testset）并组装可自动回归的 Evaluation Pipeline，用自动化指标驱动 Prompt 和模型迭代。

---

### Q3: 为什么说做 Agent 评测必须看“执行轨迹 (Trajectory)”？
* **答题要点**：避免“黑盒误判”。Agent 可能蒙对答案但绕了 10 步远路、调用了未授权的工具或产生过高的 Token 成本；通过 5 档松紧比对（精确匹配 ➔ 按序匹配 ➔ 任意序 ➔ Precision/Recall ➔ 单一工具使用）精准定位在哪一步决策失效。

---

## 📌 第二部分：核心组件与技术细节

### Q4: 如何科学评估一个 RAG 系统？
* **答题要点**：必须切分为**“检索段 + 生成段”双段评测**：
  * **检索段**：看 Context Precision（相关切片占比）、Context Recall（关键证据召回率）、NDCG/MRR 排序指标；
  * **生成段**：看 Faithfulness（生成回答是否严格扎根于检索证据，杜绝无中生有）与 Answer Relevance。

---

### Q5: 如何评测 Agent 的工具调用能力？
* **答题要点**：
  1. **能力层、行为层、代码层** 三层架构；
  2. 构建“Query + 可用工具列表 + Expected 标准答案”三件套；
  3. 逐项核对：工具名 ➔ 必填参数 ➔ 防参数幻觉 ➔ 参数类型；
  4. **必须注入反例**：测试纯闲聊场景下 Agent 是否能克制不乱调工具。

---

### Q6: 如何设计多轮交互评测用例？
* **答题要点**：拒绝写死固定对话文本。采用 **“环境配置 + 隐藏用户目标卡 + User Simulator（大模型模拟器）+ 终态 Rubric”** 架构。在模拟器中注入“首轮模糊表达”、“中途改口纠偏”和“闲聊干扰”，最后用代码断言终态，用 LLM Judge 评估语义行为，并用 $\text{Pass}^4$ 验证稳定性。

---

### Q7: 多 Agent 团队协作如何进行评测？
* **答题要点**：
  1. **交接轨迹评测 (Handoff Trace)**：验证谁把什么字段传给谁；
  2. **消融实验 (Ablation Study)**：对比 Full Team vs No Router vs Single Agent，评估新增 Agent 的边际收益；
  3. **过程监控与质检 Reviewer**：抓取团队死循环、重复调用与状态冲突。

---

## 📌 第三部分：工程落地与线上运维

### Q8: 发布闸门（Release Gate）应该卡哪些红线？
* **答题要点**：5 大并列闸门：功能成功率（$\ge 95\%$）、轨迹与规划错误率（$0\%$ 工具误调）、成本与时延预算（P95 达标）、安全红线（$100\%$ 越狱防御与 $0$ 敏感信息泄露）、业务可用性（人工兜底率 $< 3\%$）。

---

### Q9: 线上如何保证 Agent 的持续质量与闭环？
* **答题要点**：
  1. **灰度发布**：1% ➔ 10% ➔ 全量，比对真实业务留存/转化；
  2. **可观测性三件套**：Logs 记录输入输出、Traces 追踪调用耗时与 Token、Metrics 告警看板；
  3. **数据飞轮**：线上捕获的 Bad Case 自动脱敏并回灌离线黄金测试集，重新跑 CI/CD 闸门，彻底杜绝历史问题回归！
